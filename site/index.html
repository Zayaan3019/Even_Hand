Did it matter which TA marked the script? And if it did, why?

Large courses are marked by teams of TAs who split the scripts, so part of a student's grade depends on whose pile the script landed in. From the marks file your course already keeps, with the written answers if you have them, Even Hand measures how differently each TA marked, whether the answers explain it, which grades it moved, and which scripts deserve a second look.

Get started Source code

🔒 Runs on your own computer. Marks, names and answers never leave it. It never changes a mark.

Why it matters under relative grading

With B at the class mean, A one standard deviation above and the top 10% at S, grading is zero-sum. A leniently marked student who rises into a band pushes a harshly marked one out of it. Comparing pile averages does not settle it either: one TA may simply have received the stronger scripts. Even Hand separates the two.

Five questions, answered in order

  1. Can this marking be checked at all?Decided from who marked what, before any mark is read. If the arrangement cannot separate a TA from their students, Even Hand says so instead of guessing.
  2. How differently did the TAs mark?Each TA's severity in marks, with a 95% interval and a test of whether the differences could be chance.
  3. Was it the answers or the marking?Answers that say the same thing are compared across TAs, so a pile of stronger answers is never mistaken for a lenient TA.
  4. What did it do to grades?The course regraded under its own rule, as if every script had been marked by an average TA.
  5. Which scripts should be looked at again?At most 20, most consequential first, plus near-identical answers that got different marks.

How it tells the marking apart from the answers

A gap between two TAs' piles has two possible causes: one pile's students wrote better answers (a legitimate difference), or one TA marked the same work differently (a marking effect).

Even Hand reads every written answer with a sentence-embedding model (all-MiniLM-L6-v2, run on your computer by its own Java implementation) and compares each answer with the most similar answers marked by other TAs. Once two answers say the same thing, what was written cannot explain a gap in their marks. This is matching with regression adjustment from causal inference (Abadie & Imbens).

The report then says how far that comparison can be trusted:

  • Decomposition. Each TA's gap = what students wrote + how it was marked + neither.
  • Overlap and balance. Does each TA have comparable answers marked by others?
  • Negative control. Answer length, which a TA cannot change and nothing adjusts for.
  • Placebo. TA labels shuffled among similar answers: the method must then find nothing.
  • Rosenbaum sensitivity Γ. How much hidden quality difference would overturn the conclusion.
  • Mechanism. Consistent severity, a different reading of one question's rubric, drift, isolated slips, or chance.

When the marks alone can compare TAs only by assuming their piles were alike, a Hausman test compares the two estimates. If they agree, the more precise marks estimate is kept; if not, the answers' estimate is used. The full method, with references.

How accurate it is, on real answers

Measured on the UNT short-answer dataset (Mohler, Bunescu & Mihalcea, ACL 2011): 2,273 real student answers to 81 questions, each graded independently by two people, so the true difference between graders is known. Each run deals every script to one grader only, as a course does, and asks Even Hand to recover what the double grading shows. Settings were tuned on half the questions; every figure below is measured on the other half.

What a professor sees

Every chart carries a short How to read this note, so it needs no training. Saved reports carry pseudonyms only; the Class Committee sheet names no TA or student.

Privacy and security

Nothing leaves the computer

The app is served by your own computer on 127.0.0.1 only, and an architecture test forbids any other network use in the code. That is why it is downloaded rather than used on this website.

Pseudonyms from the first step

Roll numbers and TA names become keyed HMAC-SHA-256 pseudonyms as the file is read. Real names appear on your screen only; saved reports never contain them.

Same file, same report

Every random draw is seeded, so running the same file twice gives the same pseudonyms and the same figures, to the last digit.

Untrusted files handled defensively

Excel files are opened with a size cap and with XML external entities disabled. The answer-reading model is checked against a pinned SHA-256 before use.

Get started: three steps, no training

  1. Download and open it.Get the code (below), then double-click even-hand.cmd on Windows or run ./even-hand.sh on macOS or Linux. The first start builds it and fetches the answer-reading model once (a few minutes, with internet); after that it starts in seconds and works offline.
  2. Drop in your marks file.The Excel workbook or CSV you already keep, or your exam platform's export, with a column saying which TA marked each script. Even Hand shows what it read and anything to fix, in plain words.
  3. Press Check the marking.The results open on a one-paragraph bottom line, with sections for the TAs, why marks differed, the evidence, grades and the re-check list.
